# Caldova Live Report prompts

The Preconfigured Agent receives both Live Reports idempotently through the supported authoring-thread, thread-message, approval, and report verification APIs. Fresh deployments use explicit create prompts; existing reports use update-only prompts that require the original report ID before SaveReport approval. The Configure Agent uses one of these specifications as an attendee authoring exercise only in the extended path.

## FinOps

Update the existing Live Report named **Caldova FinOps** in place and preserve its report ID and history. Use only `caldova-finops_get_caldova_finops`, the repository-owned stdio MCP tool running inside the SRE Agent container with its managed identity. The tool is hard-scoped to the configured learner subscription and resource group and exposes no inputs or writes. Every refresh must cascade from resource-group-scoped Cost Management `ActualCost`, forecast/budgets/anomalies/Advisor where supported, through consumption usage, then to labeled inventory plus Azure Retail Prices estimates. Keep actual, forecast, estimate, and potential savings separate; unknown is never zero. When the connector returns `freshness.status: cached`, show the billed value as **last-known-good**, its original `costCapturedAtUtc`, cache age, and throttle reason; never present it as a new live query. Include freshness/provenance, useful partial results, charts, sortable findings and driver tables, optimization candidates, reliability context, explicit unknown states, and no write actions. The current specification marker is `CALDOVA-FINOPS-V2`.

## Operations Command Center

Update the existing Live Report named **Caldova Operations Command Center** in place and preserve its report ID and history. Keep the current overview as the first tab named **Operations Overview**. Add **Dependency Mapping**, a live logical request/dependency map with status, direction, timestamps, provenance, unknown states, and resource links. Add **Resource Explorer**, a searchable/filterable/sortable inventory of resources discoverable through the supported read-only Azure connector. Do not depend on direct Log Analytics queries or expose write actions. Resource Graph, raw ARM configuration, alert-instance, or scheduled-task evidence that the connector cannot expose must be labeled UNKNOWN rather than inferred. The current specification marker is `CALDOVA-OCC-V2`.
